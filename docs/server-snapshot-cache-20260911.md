# 服务端短期快照与增量刷新：2026-09-11

本阶段只缓存飞书权限计算所需的原始来源，不缓存个性化工作台响应，也不缓存周报、文献、财务单据或学习记录。每次响应仍按当前登录人重新计算可见项目和页面内容；所有写操作继续重新读取权限并跳过快照。

| 来源 | 新鲜期 | 最长使用期 | 过期行为 |
|---|---:|---:|---|
| 人员表 | 12 秒 | 20 秒 | 等待飞书新读，失败则拒绝 |
| 项目成员关系表 | 12 秒 | 20 秒 | 等待飞书新读，失败则拒绝 |
| 正式项目表 | 30 秒 | 45 秒 | 等待飞书新读，失败则拒绝 |
| 权限项目镜像 | 30 秒 | 45 秒 | 等待飞书新读，失败则拒绝 |

新鲜期内直接使用快照；新鲜期结束但未到最长使用期时，当前请求使用有界快照，同时由 Worker 在后台更新。超过最长使用期后不允许使用旧值。来自同一来源的并发刷新合并为一次飞书请求。

短时只读上下文的到期时间取 30 秒与权限快照剩余使用期中的较小值。因此快照和只读上下文不会串联成更长的权限延迟。工作台修改正式项目后会立即删除正式项目快照；外部直接修改飞书权限表则受上表最长使用期约束。

响应通过 `X-ER2-Snapshot` 标记 `miss`、`hit`、`stale` 或 `refresh`，并继续提供 `Server-Timing`。`/api/v2/health` 公开当前开关和时限，不包含表标识、记录或凭证。

紧急关闭只需将 `SERVER_SNAPSHOT_CACHE` 改为 `false` 并重新部署；不需要删除业务记录、Durable Object 或飞书表。缓存键包含应用、来源绑定和表标识，绑定变化会自然切换到新快照空间。
