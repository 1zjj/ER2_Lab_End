# 读取稳定性优化：2026-09-08

本批只处理审计确认的重复读取、可选模块故障扩散、读取排队及等待恢复。周报五项、原记录、保存协调器、项目授权规则、入组指南阅读存储和学习消息接收规则保持原有业务含义；没有修改飞书知识库或人员/项目授权，没有创建测试业务记录。

| 改动 | 保留的保护 |
|---|---|
| 登录、本人身份、普通个人周报使用人员身份核验；存在项目范围的历史/编辑按需读取项目授权 | 人员账号和编号唯一、有效状态；非空或异常项目范围仍检查有效授权；未获授权的项目记录不返回、不允许改写 |
| 主页重用本次鉴权已读取的人员快照 | 只在当前操作内使用，没有跨请求人员/权限缓存；写入前重新读取身份 |
| 文献、项目展示、旧课程、任务和链接读取单独报告失败 | 人员与周报主表依旧为必需；未知数量不显示为零；受影响模块禁止用空记录假装正常 |
| 学习 GET 不进入写入队列，读取使用短存储事务 | 每次从人员表验证访问资格；原写入串行、存储事务、追加事件、幂等和通知队列不变 |
| 历史和身份读取按阶段预算执行；主页整体等待预算 25 秒 | 超时不会绕过鉴权或认为记录不存在；不自动重放业务写入 |
| 提交等待上限 45 秒，原草稿和请求标识保留 | 后端结果不确定仍由既有协调器核对，不能因为客户端超时重复创建周报 |
| 搜索目录加载与生产主页启动独立 | 搜索元数据故障不再卡住登录后的主页 |
| 文献移除不相关的周报绑定要求 | 原文献身份、输入校验及当前共享范围未改变 |

固定单页模拟条件下的上游调用数：本人身份 3→1，个人周报历史 4→2，周报专页 5→2，主页 9→8，普通周报保存 13→7。项目范围周报仍须额外读取授权表。上述为调用数，不是承诺的线上耗时。

响应包含 `X-ER2-Read-Version: read-stability-v1` 与 `Server-Timing`。较慢请求、失败请求及部分模块失败会记录 `ER2_READ_TIMING`，内容包含请求编号、路由、各表读取时间及错误类别，不包含账号、令牌、表内文本或提交内容。`/health` 包含 `readPatch` 标记。借此进一步区分飞书上游延迟与业务处理时间。

发布前验证：现有 Worker 全部回归、真实 workerd/SQLite 周报和学习存储测试、前端周报/入组/诊断/课程门控回归；新增人员读取故障、项目授权故障、项目到期、写入前撤销身份、学习跨用户慢请求、读取期限、页面备用请求共享期限和旧响应隔离测试。

本批未包含：文献跨请求并发幂等、团队外共享边界调整、旧入组写入接口退役、完整搜索/入口修补、周报反馈往返、财务和设备功能。它们仍是审计清单中的后续事项，不能因本批发布而标为已完成。

线上验收只读取主页、周报历史、学习目录/记录和管理诊断，不新增真实周报、课程记录或测试消息。真实第二账号及通知送达验收仍独立进行。

本批不修改持久化存储布局，也不引入新的命名空间。若发布后出现回归，应使用发布脚本保留的上一版代码及配置回退，不手工重建或清空记录。
