# 周报读取隔离与管理员逐表诊断

启用现有周报策略时，非指定审核人按本人 OpenID 分别查询本周、上周，并合并去重。无论筛选查询还是兼容性全表回退，服务器先限制周次与 canReadWeekly 可见范围，再进行 accessForRecords 项目验权。

不取消本人项目关联记录的项目验权，不改变指定审核人、成员分类、职责、项目授权、写入、历史、草稿或图片规则。其他人的记录及时间范围外记录不再造成个人周报对项目表的额外依赖。指定审核人的项目归属展示保留原有独立短预算读取。

管理配置 → 数据源诊断 → 检查逐表错误与耗时：GET /api/admin/read-diagnostics。执行前后重新核验管理员身份；并行检查人员、周报、项目主表、项目权限镜像、项目成员关系五个固定来源。跳过快照，对每表保留独立结果和 8 秒读取预算。一表失败不掩盖其他表结果；HTTP 200 表示诊断运行完成，readComplete 才表示所有表读取成功。

返回仅含固定绑定名、耗时、记录数量或错误码、状态、诊断编号；不返回原始人员和周报内容、凭证、原始错误信息。只读，不触发同步、授权或修复。普通模块卡片显示经过转义的已有错误消息及诊断编号。

测试：npm run test:read-isolation；npm test。包含筛选及全表回退、他人数据不泄漏、本人关联项目仍失败关闭、时间范围、非管理员拒绝、逐表部分失败与错误脱敏。
