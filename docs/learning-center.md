# 学习中心：课程记录与权限边界

版本：`learning-text-v1`，2026-09-08。

学生主页保留一张学习中心卡片。点击后打开固定高度、内部滚动的学习弹窗。Track A 可折叠并列出 Lesson 01–10；Track B/C 保留未开放的位置，不计入完成进度。

## 使用方式

1. 从[工作台学习中心](https://1zjj.github.io/ER2_Lab_End/?page=learning)打开本课教材，在原飞书知识库页面阅读。
2. 完成后提交文字：**学习与收获必填**；疑惑与问题、建议与反馈选填，每项最多 10000 字。不上传图片或附件。
3. 后端确认持久保存后，本课显示“已提交”。学生可继续任意下一课，不必等待朱俊杰回复、评分或确认。
4. 已提交原文保留；后续内容通过“补充说明”追加。朱俊杰在教师汇总页或管理配置的“学生学习记录”入口查看并回复。原文、补充和回复均保留时间与作者，可翻看更早记录。
5. Track A 的十课均已提交后，独立通知队列向陈铮一教授发送一次“xxx同学已完成Track A的学习”。教授不因此获得逐课原文访问权限。

## 数据实际保存在哪里

| 内容 | 位置 | 与其他流程的关系 |
| --- | --- | --- |
| 课程教材 | [01.1 学习中心](https://lcnywl4yrecr.feishu.cn/wiki/AMikwNK58iWRCbkvoBJcQ7Q3nmc)及原 Lesson 子页面 | 课程正文仍由飞书原有文档权限控制 |
| 十课目录与精确链接 | `worker/src/learning-catalog.js` | 后端提供同一份目录；未来增加 Track 时修改此处 |
| 学生逐课文字、补充与朱俊杰回复 | Cloudflare `LEARNING_RECORDS` 独立 Durable Object 存储，实例名 `er2-learning-text-v1` | 不写入周报表、90.3 培训资质记录或人员表；没有新增飞书问卷 |
| 通知待发送项与送达凭据 | 同一学习存储的独立队列与凭据 | 不借用周报自动化日志或周五定时任务 |
| 原 90.3 培训记录、签字、到期复训、设备资质 | 原飞书表，保留不动 | 普通课程提交不等于实操合格、资质通过或设备上岗授权 |
| 周报五项内容和历史 | 原 90.2 周报表及现有周报接口 | 学习模块不写入或覆盖；每周学习概述仍可写在周报的“学习与方法”中 |

新增的是后端独立的学习记录存储，不是复制现有培训表。隔离原因：90.3 培训记录已有签字、资质、复训字段与自动化，原课程接口还使用教授周报接收职责查看逐课记录，均不适合直接继承新普通课程的语义和可见范围。

存储保留事件、请求去重凭据和通知送达凭据；没有业务删除接口。SQLite Durable Objects 支持平台提供的时间点恢复，运维操作见 [Cloudflare 存储文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)。不要删除命名空间或修改实例名来“重新初始化”学习进度。

## 独立权限

| 身份 | 普通课程 | 学生原文与回复 | 可修改的内容 |
| --- | --- | --- | --- |
| 在组、团队内的学生身份 | 阅读目录、提交本人记录 | 仅本人 | 首次提交、追加本人说明 |
| 指定朱俊杰 | 阅读教材与学习记录收件箱 | 可查看学生原文并回复 | 追加回复；不能覆盖学生原文 |
| 陈铮一教授 | 按原飞书文档权限阅读教材 | 不通过课程接口查看逐课原文 | 仅接收全部完成通知 |
| 其他管理员或课程审核人 | 仍按其本人的普通课程身份处理 | 没有额外查看权 | 不继承朱俊杰的收件权限 |
| 离组、停用、重复账号、空编号、团队外成员 | 接口拒绝访问 | 接口拒绝访问 | 无 |

每次学习 API 请求重新读取 90.1 人员主表并核验账号唯一性、人员编号、在组状态及团队边界。不读取或修改项目授权表，不把完成数量写回培训状态、人员状态或设备资格。

课程接收人使用专用配置：`LEARNING_REVIEWER_PERSON_ID=P-002`、`LEARNING_PROFESSOR_PERSON_ID=P-001`，同时核验姓名和已有课程审核/PI 职责。不使用周报的 `PROFESSOR_OPEN_ID` 或“教授周报接收”职责作为课程查看授权。

## 保存与通知保障

- 同一课程首次提交不会覆盖现存原文；再次提交应走追加说明。
- 请求 ID 与内容哈希共同去重。断网后使用同一请求和内容重试；收到持久保存确认才清除草稿和更新进度。
- 每个历史事件单独保存，按页读取；30 条显示上限不代表删除更早记录。
- 草稿按登录账号、课程和操作类型隔离。切换账号后，迟到的网络响应不能显示到新账号页面。
- 通知失败不改变已保存状态或阻止继续学习；收件人在发送前再次核验。不会在日志或消息中附上学生正文。
- 成功通知保存送达凭据；结果不明确时只在飞书 UUID 去重时间窗口内重试，超时转为待核对，在朱俊杰收件箱提示。不能声称网络异常场景下消息一定送达。
- 新版启用时，旧 `/api/courses/submit`、`confirm` 路径保持关闭，避免两种完成规则并行生效。

## 发布与验收

发布前运行 Worker 全部回归测试、学习权限/记录/通知测试、真实 workerd + SQLite 运行测试以及学习弹窗 DOM 测试。首次引入学习命名空间时，先部署保留旧业务代码和周报存储的兼容版本，作为回退目标。

GitHub Pages 只有在周报能力与学习存储、接收人检查同时通过后才发布。线上健康检查字段为 `capabilities.learning`；通过表示存储及指定人员配置可用，不等于两位用户已完成实际收发验收。

仍须真实第二账号完成以下验收：学生打开十课教材的飞书权限；学生提交本人真实学习记录；朱俊杰收件和回复；学生查看回复；实际全部完成后教授收到提醒。自动测试使用模拟人员与消息，不向真实成员发送测试消息，不产生测试周报。
