# 身份首屏与周报结果核对

本次修复独立于 P-007/P-008 待发布配置，从已发布版本建立隔离工作目录；不改人员、项目授权或飞书 ACL，不删除任何业务记录、回执或待确认 journal。

## 首屏

- 前端仅请求 `/api/dashboard/start`，身份失败保持 fail-closed；不会在同一失败后重复请求人员或聚合首页。
- 身份确认后周报、项目、文献独立读取，管理详情/待办按需加载。一个模块失败不会撤掉整个页面，不显示虚假的零条记录或未提交状态。
- 同一模块的并发重试合并；确认保存后的刷新可排在当前读取之后，不使用旧响应覆盖保存结果。
- 明确的 MODULE_FORBIDDEN 仅影响模块；身份失效、未知的权限拒绝及登录过期仍清除私人界面。未放宽后端验权。

## 周报保存

- 外层请求设置 32 秒的服务端时间预算，传入原有按人隔离的写入协调器，包括排队耗时。客户端仍保留原 45 秒保存超时。
- 保存前后按本人 OpenID 与目标周筛选，保留原有字段兼容回退、重复记录检查、版本校验、写前重新验权和严格单次写入。
- 写入前不足 3 秒预算时不开始远端写入。已经发出的写入若未确认，继续保留 journal，绝不将网络错误当作“没有保存”。
- 补交弹窗显示进行中状态，允许同账号后台数据对象刷新，不再静默忽略提交。账号变化仍阻止继续使用旧表单。

## 只读结果核对

`GET /api/reports/status?weekId=...&requestId=...` 经原有身份验证路由到该人员的协调器，不进入写入队列。

- saved：本人目标周、请求 ID 和已存在的回执/待确认内容散列核验一致，返回正式记录。
- processing：原请求仍处理，不重发。
- needs_verification：存在无法确认的 journal/回执或重复记录，保留并提示人工核对。
- different_submission：该周已有其他提交，不覆盖。
- not_found：本次查询未找到对应记录及 journal；仅提示保留原内容、原请求 ID 重试，不自动 POST。

结果核对不会删除 journal 或创建/修改周报。普通周报和补交超时后使用 GET 核对；再次打开未确认表单先核对再允许写入。查询失败时保留草稿；核对旧提交不能清掉用户后来新增的未提交文字。

## 验证

测试覆盖身份唯一首屏、单模块失败/重复重试、403 分类、同账号数据替换、超时只查询不重发、重开表单、已保存但原请求未返回时的独立查询、跨用户拒绝、journal 保留以及原有功能回归。

未做真实提交或发送通知。需人工介入的旧待确认记录不会被自动清理；处理具体个案前必须核对其正式记录与请求回执。
