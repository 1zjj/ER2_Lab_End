## 发布约定

- `worker/release-checks.mjs` 保存已核对的六张业务表定位的 SHA-256 摘要，不公开实际定位值。发布先只读检查 Cloudflare 当前绑定；不匹配时停止，不能凭旧表 ID 覆盖当前生产。
- wrangler 使用 `keep_vars: true`，不在代码部署中轮换 Feishu App Secret 或 Session Secret。旧的人员/周报表 ID 不再写进默认配置。
- `npm run release:check` 仅预检；`npm run deploy` 预检后发布。GitHub main 的 Worker 工作流调用同一脚本。
- 发布前检查核心健康、匿名请求拒绝和回退版本；发布后要求 `/health.release.commit` 等于本次 Git SHA，并再次核对绑定。
- 有效版本和核心检查失败时，恢复本次发布前的版本，再检查恢复结果。检测到其他人发布的新版本时不覆盖它；无法识别上传版本时报告人工核验，不猜测回退目标。
- 构建时生成 commit/builtAt；`/health` 和 `/api/v2/health` 同时展示。默认本地源码值为 null，不能冒充生产发布。
- `coreReady` 指核心身份与周报读取检查，`configured` 仍保留全部配置状态；课程未配置不再掩盖核心检查结果，也不会被伪装成已配置。
