# 教授周报汇总：原文拼接版

## 本次范围

只更新 ER² 工作台关联 Worker 的教授周报发送链路。原有登录、人员权限、课程、入组、周报写入、文献阅读、教师反馈和周五提醒保持原实现。没有删除 AI 配置、密钥或知识资料，也不启用任何模型调用。

本文件是关联代码的实现记录，不代表已经逐项核验或修改飞书原生自动化/Aily 管理后台。外部已存在的原生 AI 流程须在获得对应后台访问后单独核验，不能用本 Worker 的暂停状态替代核验。

## 接收格式

周五 18:00（Asia/Shanghai，北京时间）向现有 `PROFESSOR_OPEN_ID` 指定的教授发送消息卡片。

1. 标题：ER² Lab 周报汇总 · 第 N 周；标注周一起止日期和统计截止时间。
2. 本周概览：已提交/应提交人数、未提交人数、填写问题/支持的人数、人工知识候选人数、文献阅读篇数/人数。
3. 需关注：未交名单和填写了问题/支持的学生姓名。不根据文本自动判断风险等级、优先级或应作出的决策。
4. 按学生完整拼接：本周完成、下周计划、学习进展、候选知识点；有内容时追加问题与支持、产出证据。
5. 页脚：按固定模板拼接学生原文，不作 AI 总结或评价；保留一个“打开教师工作台”入口。

少量学生合并成一张卡片；超过安全消息体积或组件预算时，自动分为带序号的连续卡片。正文不按人数或字数截断，不使用“只看前五位”。原文在飞书消息中直接可读，工作台链接仅作补充。

## 字段映射

| 教授显示 | 数据来源 | 空值处理 |
|---|---|---|
| 本周完成 | 本周完成与结果 / 本周完成 | 未填写 |
| 下周计划 | 下周计划 | 未填写 |
| 学习进展 | 学习与方法 / 学习进展 | 未填写 |
| 候选知识点 | 候选知识点（人工文本） | 未填写（不自动生成） |
| 问题与支持 | 问题与阻塞 / 阻塞 | 不展示空段；“无/暂无”等不计入需关注 |
| 产出证据 | 证据链接 | 不展示空段 |

**候选知识点接入边界：** 当前 `saveReport` 的既有写入字段没有独立的“候选知识点”，本次没有假定飞书中该字段已经存在，也没有改变飞书表结构。新汇总读取该同名人工字段（如已有），否则保留空值提示。不能宣称学生网页已经新增了可独立提交的候选字段。后续接入独立表单项需要同步修改表结构、提交接口、编辑回填和教师详情，不能只增加一个展示标题。

## 统计与发送规则

- 应交人数：人员表中启用中的学生，按 OpenID 去重，沿用现有全实验室教授汇总范围。
- 纳入内容：本周正式“已提交”的记录；草稿、停用学生及人员表以外的记录不纳入学生正文。
- 同一学生有重复记录：使用截止时间之前最新的正式提交版本。
- 缺少有效提交时间的历史记录保留但明确提示人工核对，不伪造时间。
- 文献概览延续实验室全体成员范围，统计本周正式提交记录，不把所有文献条目塞进周报正文。
- 以完整序列化请求的 UTF-8 字节数做预算；每条预留到 24,000 字节以内，并限制组件数量。
- 用户填写内容使用纯文本组件，避免把正文中的 Markdown 或 @ 文本解释为可执行的消息标记。
- 延用每周汇总运行键；每一分条保留稳定消息 UUID 和自动化日志，成功周不重复发送。
- 分条发送中断后，如数据发生变化，停止自动续发并报错，避免把不同版本拼在同一份周报里。
- 未配置自动化日志表时，只有消息 UUID 的平台去重保障，不能声称具备长期严格的 exactly-once 保证。
- 既有周报写入会覆盖同人同周记录，因此这不是历史版本归档系统，不能据此重建任意过去时刻的快照。
- 部署不会立即补发以前的周报，也不会向教授发送虚构演示数据。

## AI 暂停但保留

当前入口 `runtime.js` 对 `/api/ai` 命名空间返回暂停状态；即使意外将环境变量设为 true，也不会启用模型。`/health` 明确返回 AI 暂停状态和原文汇总格式。

| 原方案 | 当前状态 | 保留的启用原则 |
|---|---|---|
| A02 + AI01 教授周报 | A02 改为固定原文汇总；AI01 暂停 | 以后 AI 只能另加摘要，不替换学生原文 |
| AI07 知识候选整理 | 暂停 | 只处理学生主动标记的候选，不扫描所有周报 |
| AI10 + AI11 ER² 知识问答 | 暂停并保留合并入口设计 | 按授权资料回答并标注来源 |
| AI13 + AI14 候选课题 | 暂停 | AI 发现候选 → 人工选择 → AI 深入评估 |
| AI15 | 原编号保留、暂停 | 本次不重新定义未核实的原功能 |
| AI22 技术分享处理 | 暂停 | 只处理正式提交，不处理草稿 |

本版不会扣除模型调用额度；常规消息/API/定时自动化的配额或费用仍按各平台规则计算，不能把“不用 AI”说成“所有服务免费”。
