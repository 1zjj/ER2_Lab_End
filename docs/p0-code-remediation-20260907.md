# ER2 P0 第二轮代码修复与绑定核对

范围：草稿隔离、主人员鉴权、项目关系鉴权及相关身份接口。财务等 P1 新功能不包含在本轮。

## 交付边界

代码以 main 03dd32fa6b105cdddc064c46f30b8f9b829f5f58 为基线，需配套绑定后切换。
本轮没有修改原生飞书 ACL、业务授权状态、其他知识库，没有发送真实消息或写入真实业务记录。
`worker/p0-bindings.candidate.json` 是空值配置模板，不包含私有资源标识；真实绑定应留在部署环境，**不会被运行时代码自动加载**。
不得直接合并并触发生产发布：当前部署仍使用旧人员表与全局 Base 备用定位，严格鉴权上线后会拒绝此配置。

## 已实现

- 草稿与请求 ID 按服务器确认的账号及周次隔离，课程另按课时隔离；迁移清除未知归属旧草稿。退出、重新 OAuth 登录、401/403 清理私有草稿并关闭表单。
- OAuth 和每个受保护 API 均重新读取主人员、项目主表及关系表。不信任登录令牌中的旧角色。
- 主人员表同时接受真实“成员编号”和历史“人员编号”；两者冲突则拒绝。账号必须唯一且与飞书人员字段一致，人员编号必须唯一，在组且边界／类别有效。
- 飞书人员字段显式请求 `user_id_type=open_id`；不将显示名称或 user_id 当作 OAuth open_id。陈铮一显示 user069701 已由用户确认，不是待核验身份问题。
- 权限链：账号 → 人员记录/P 编号 → REL 关联记录 → 90.1 PRJ → 90.2 统一项目编号。人员表“关联项目”反向 REL 显示值不用于直接匹配 PRJ。
- 只有审批状态有效、落实状态已落实、审批人存在、日期有效且边界一致的单人单项目关系可授予工作台权限。关系状态不会修改原生飞书 ACL。
- 管理包含编辑与只读；编辑包含只读。管理项目名称和编辑里程碑／阻塞分开检查。系统管理员没有绕过项目关系的通用项目权限。
- 同一人同一项目重复关系、重复 PRJ、重复业务映射均拒绝，防止异常数据扩权；暂停项目只读，非明确允许的项目状态拒绝。
- 项目列表、详情、PATCH 及仪表盘按统一 PRJ 筛选；个人周报／课程中带项目范围的数据也检查项目权限。未知写字段拒绝。
- 课程审核根据当前人员“系统职责”判断；写入前重新核验身份及资源权限。教授周报发送检查接收者当前状态和职责，缺少日志表时不发送。
- 非法令牌稳定返回 401；缺失权限绑定返回 503；读取失败不回退宽权限。分页不完整拒绝使用部分人员／关系数据。
- 深度健康检查分别解析每张表所属 Base，增加读取超时，缓存随绑定变化失效。健康响应提供第二轮补丁标记及严格鉴权绑定状态。

## 模拟验证与限制

运行 `cd worker && npm test`。测试通过实际 Worker fetch 入口和签名模拟会话执行，飞书网络均替换为受控响应；不会给真实用户发消息，也不会写飞书数据。
覆盖新增人员、重复账号／编号、离组旧会话、跨项目 GET/PATCH、只读、编辑／管理包含关系、职责撤回、到期／撤销／待核验、重复关系、暂停项目、PRJ 映射及草稿迁移／换账号／换周次。
既有周报、阅读、课程与教授周报格式测试继续运行，测试夹具迁移到主人员结构。

模拟通过不等于真实账号验收。仍需验证：飞书 API 对目标三表的实际读取、写字段是否存在且可写、统一编号完整性、第二账号端到端、原生 ACL/分享/导出/仪表盘。
跨 Base 无分布式事务：写入前复核缩小竞态窗口，但不能宣称撤权和正在执行的飞书写入原子同步。飞书表格本身也没有因此获得强制唯一约束；异常重复数据由应用拒绝使用。

## 生产切换顺序

1. 使用只读预检 `node worker/check-p0-bindings.mjs`，在部署环境注入现有飞书应用凭证和表绑定（空模板不会覆盖环境中的绑定）；输出仅为计数、字段缺口与结论，不输出凭证或人员详情。
2. 确认 master 人员账号可解析，90.1 三表可读、90.2 PRJ 映射唯一且写字段兼容。保留现有周报、阅读表各自显式 Base 绑定，不把它们迁入 90.1。
3. 在部署环境按已核对的实际数据表填写模板，逐项应用到部署配置，清除这些表冲突的旧 `*_BASE_APP_TOKEN`；不要只新增 wiki 定位却留下优先级更高的旧 app_token。
4. 对照真实授权意图验收当前关系；待核验关系保持拒绝，不批量改成“已落实”以绕过审批。
5. 发布代码后核对补丁标记和健康状态，进行本人基本访问与第二账号隔离验收。原生飞书权限单独验收。

接口参考：[飞书列出记录文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/bitable-v1/app-table-record/list)。
